# Dual Codex Day v0.23.0

v0.23.0 把 Profile、工作目录和客户端入口保存为可复用的最近工作，让启动中心可以直接继续上次任务。

## 主要变化

- 客户端成功启动后自动记录工作组合，相同组合再次使用时只更新次数和时间。
- 启动中心优先显示“继续上次工作”，并展示固定项和最近项。
- 工作组合支持固定、取消固定、移除，以及失效目录的重新选择。
- 当前工作组合仍在运行时，运行实例保留独立关闭入口。
- 打包版启动时恢复最近一次有效工作目录。

## 启动流程

- 点击工作组合后，由主进程根据本地记录解析 Profile、目录和固定入口。
- 目录与入口可用后切换启动上下文，再执行 v0.22 的即时只读预检。
- 警告项继续要求确认，阻断项继续禁止启动。
- Profile 已删除、目录缺失或入口不可用时，不会回退到其他组合。

## 数据边界

- 最近工作使用独立的版本化 `work-combinations.json`，不修改 Profile schema。
- 最多保留 24 条记录，固定项最多 8 条；未固定的旧记录会自动淘汰。
- 渲染层只提交工作组合 ID、固定状态或移除请求，不能指定任意启动参数。
- 本机工作目录不会进入 Profile 导出、迁移文件或诊断报告。

## 验证范围

- 模型测试覆盖去重、使用次数、固定上限、历史容量、目录修复、删除和损坏文件。
- Electron 检查覆盖继续工作、预检复用、固定、目录修复、移除和打包图标。
- 桌面截图覆盖上次工作、固定组合和活动实例的并列展示。
- 发布检查覆盖版本元数据、变更记录、Release Notes、官网版本、Windows 打包冒烟和当前产品截图。
- Windows Terminal 的一次性 PID 握手使用随机临时文件，避免 Profile 目录权限差异导致 CLI 已打开但无法登记。
