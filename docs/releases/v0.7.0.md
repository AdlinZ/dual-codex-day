# codex-day v0.7.0

v0.7.0 让 codex-day 从“能够持续统计”进一步变成“能够解释自己的数据状态”：页面现在可以看到索引是否健康、哪些记录被跳过、历史保留多久，以及数据库当前处于什么状态。

## 主要变化

- SQLite Schema v2 记录每个日志文件的解析结果，并自动兼容迁移 v0.6.0 数据库。
- 页面右上角增加数据健康入口和诊断侧栏，展示刷新、范围、索引大小、保留策略与异常分类。
- 新增 `--retention-days`，支持只保留 SQLite 最近 N 天事件；扩大周期时自动重扫恢复历史。
- 新增 `doctor` 与 `doctor --json`，默认输出脱敏、只读的本机诊断结果。
- `/healthz` 保持轻量，详细脱敏状态由 `/api/status` 提供。
- Tag 发布会同步生成 `linux/amd64` 与 `linux/arm64` 的 GHCR 镜像。

## 快速自检

```powershell
node .\scripts\codex-day.mjs doctor
```

## 设置历史保留

```powershell
node .\scripts\codex-day.mjs --retention-days 90
```

Docker 用户可以设置 `CODEX_DAY_RETENTION_DAYS=90`。默认仍为 `all`，升级后不会突然丢失历史统计。

## 隐私边界

- 保留策略只清理 SQLite 索引，不删除或改写 Codex 原始 JSONL。
- 页面、状态接口和默认自检不输出完整文件路径、原始 Session ID、日志正文或失败行。
- Token 与成本数据仍完全来自本机日志；预计成本不代表公司中转站实际账单。
