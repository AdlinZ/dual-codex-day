# codex-day v0.7.0 规划

状态：已实现，待发布验证。

## 版本主题

**数据健康与可控保留**

v0.6.0 已经解决持续运行、增量索引和跨环境部署。v0.7.0 不继续增加统计图表，重点回答三个更基础的问题：数据是否完整、异常发生在哪里、个人历史数据保留多久。

## 版本目标

1. 用户无需查看终端即可判断数据源、解析和索引是否健康。
2. 用户可以限制 SQLite 索引的历史保留周期，且不会删除或改写 Codex 原始日志。
3. 用户可以通过一条命令获得适合排障和反馈的脱敏诊断结果。
4. 正式版本自动发布可直接拉取的 GHCR Docker 镜像。

## 交付范围

### 1. 页面数据诊断中心

在页面顶部增加低干扰的健康状态入口，打开后展示：

- 最近一次成功刷新时间和当前刷新延迟
- 发现的日志文件、任务和 Token 事件数量
- 本轮新增、变化、未变化和已移除文件数量
- 有效事件、重复事件、无 Token 记录、无效 JSON、无效时间戳等解析结果
- SQLite 文件大小、当前 Schema 版本和历史保留策略
- 定价覆盖率仍归预计成本区域，不与数据完整性混为一谈

状态分为 `正常`、`需留意`、`异常`。单个损坏日志只产生可解释的警告，不应导致整个服务退出。

页面和接口只暴露汇总计数、时间与脱敏类别，不输出完整文件路径、原始 Session ID、日志正文或解析失败行。

### 2. 结构化解析诊断

SQLite Schema 升级到 v2，为每个日志文件记录：

- 总行数与可解析 JSON 行数
- Token 记录数与最终写入事件数
- 重复、空用量、无效时间戳和无效 JSON 计数
- 最近索引时间、数据时间范围和解析状态

解析器返回结构化诊断结果，不再静默吞掉所有异常。数据库迁移必须兼容现有 v0.6.0 索引，不要求用户手动删除数据库。

### 3. 索引保留与清理

新增 `--retention-days <all|30|90|180|365>`，默认值为 `all`，保持现有行为。Docker 同时支持 `CODEX_DAY_RETENTION_DAYS`。

行为约束：

- 只清理 SQLite 中超出周期的事件，不删除 Codex JSONL 原始日志
- 当前保留策略和最早索引日期在诊断中心可见
- 缩短周期后立即清理；扩大周期或切回 `all` 时自动重新扫描来源文件，恢复可用历史
- 策略变化、清理数量和恢复扫描均进入诊断摘要
- 清理在事务内完成，失败时保留原索引状态

v0.7.0 不开放浏览器写入本地设置的接口。保留策略通过启动参数或容器环境变量配置，避免引入本地写接口及其安全边界。

### 4. 脱敏自检命令

新增：

```text
node scripts/codex-day.mjs doctor
node scripts/codex-day.mjs doctor --json
```

输出版本、Node.js 版本、数据目录可读性、日志目录状态、数据库状态、索引统计、最近错误类别和服务配置。默认不输出私人路径；需要定位本机路径时再显式使用 `--verbose`。

自检命令为只读操作，不触发索引清理或原始日志修改。

### 5. GHCR 镜像发布

版本 Tag 通过后发布：

- `ghcr.io/adlinz/codex-day:v0.7.0`
- `ghcr.io/adlinz/codex-day:0.7`
- `ghcr.io/adlinz/codex-day:latest`

镜像至少覆盖 `linux/amd64` 和 `linux/arm64`。发布前继续执行页面、索引、服务、托盘、容器和生成文件一致性检查。

GitHub 个人账号下的新 GHCR 包首次发布默认为私有，官方没有提供由 Release 工作流直接修改可见性的 REST 接口。首次推送镜像后需在 GitHub Packages 设置中将其切换为 `Public`；工作流会注销登录并执行匿名镜像检查，未公开时不会继续创建 GitHub Release。后续版本无需重复设置。

## 不在 v0.7.0 范围

- 删除、压缩或修改 Codex 原始 JSONL 日志
- 公司中转站真实账单或账号级费用对账
- 云端同步、多用户账号或远程访问
- 浏览器内修改服务端配置
- 新增更多报告、图表或 AI 总结

## 验收标准

- v0.6.0 数据库可无损自动迁移，既有统计结果在默认 `all` 策略下不变
- 包含无效 JSON、无效时间戳或未知记录的日志不会中断索引，并能在页面与 `doctor` 中看到对应计数
- 未变化文件仍不会重复解析
- 从 `all` 切到 30 天后只减少 SQLite 事件；原始日志内容与文件数量不变
- 从 30 天切到 90 天或 `all` 后，历史数据会通过重新扫描恢复
- `/healthz` 保持轻量且不泄露诊断细节，详细信息由 `/api/status` 提供
- 生成的个人页面、数据库和诊断输出均不进入 Git
- GHCR 的 `v0.7.0` 镜像可启动并通过健康检查
- Windows 本地入口、托盘恢复、静态 Demo 和现有导出功能无回归
