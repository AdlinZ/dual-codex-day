# Dual Codex Day v0.10.0 规划

状态：Electron 桌面版已实现，双桌面实例已验证，待真实账号登录验收。

## 版本主题

**统一桌面控制中心**

v0.10.0 将多账号启动器和今日用量摘要整合进一个 Electron 窗口。原有 Node.js 核心、网页仪表盘、原生 Windows 启动器和命令行入口继续保留。

## 交付范围

1. Electron 主窗口展示账号配置、启动目录、客户端入口状态和最近启动记录。
2. 支持新建隔离账号配置，并一键启动 Codex CLI、VS Code 或实验性桌面客户端。
3. 从现有 SQLite 索引只读展示默认账号的今日 Token、调用、任务、缓存率和主要模型。
4. 在独立 Electron 窗口中打开完整本地用量仪表盘。
5. 提供 Windows x64 打包命令和 GitHub Release 压缩包流程。
6. 持久记录启动历史，显示每个 Profile 的运行实例数量并自动刷新。
7. 每个 Profile 支持 OpenAI 官方登录或独立中转站配置，并提供保留通用设置的完整 TOML 预览。
8. 中转站支持 CDC 安全密钥、Codex 登录和无需认证三种模式，以及 Provider ID、推理强度、交互个性和旧版响应存储兼容项。
9. 可以从用户选择的 `config.toml` 导入插件、MCP、通知和桌面偏好等通用配置，同时剥离来源活动供应商。

## 安全边界

- 渲染进程启用沙箱和 Context Isolation，关闭 Node Integration。
- 预加载脚本只暴露固定的账号、目录、启动和仪表盘命令。
- Profile 名称和 ID 必须经过现有核心校验，渲染层不能提供任意命令或文件访问。
- Electron 代码不读取、复制、展示或引用 `auth.json`。
- 配置导入只接受用户选择的 `config.toml`，不导入来源模型、活动供应商或认证文件。
- 中转站 API Key 只由 Electron 主进程使用操作系统安全存储加密，渲染进程不能读取或解密。
- `profiles.json`、`config.toml`、启动历史和日志不得包含中转站 API Key 明文。
- 详细仪表盘继续只监听 `127.0.0.1`，不新增远程 API、遥测或云端同步。
- 默认 `%USERPROFILE%\.codex` 与现有 Profile 数据目录保持兼容。

## 明确不做

- 在 Electron 内嵌官方登录页面或接管登录凭据
- 删除账号配置或自动清理账号数据
- 将不同账号的聊天记录合并到一个数据库
- 后台更新价格、应用或官方 Codex 客户端
- 自动发送可能产生费用的中转站连接测试
- 承诺所有 Codex 桌面版本都支持稳定多实例

## 验收标准

- `npm run desktop` 可以打开完整桌面控制中心。
- 创建 Profile 后，列表立即更新且目录仍使用随机 ID。
- 不可用入口必须禁用并显示“未找到”，不能在点击后才静默失败。
- 详细仪表盘可以复用已有服务，或由 Electron 启动本地服务后打开。
- 1280x800 与最小窗口尺寸下没有遮挡、横向溢出或文本截断失控。
- `npm run package:electron` 生成可启动的 Windows x64 应用目录。
- 完整自动化测试继续覆盖旧入口，并新增 Electron 安全边界检查。
- 两个不同 Profile 可以同时保留独立 Codex 桌面主进程，并使用不同的 `CODEX_HOME` 与 `--user-data-dir`。
- 控制台能够区分运行中和已关闭的实例，重启控制台后仍可读取最近启动历史。
- 两个 Profile 可以持久保存不同的供应商、Base URL、模型、认证方式和高级模型选项。
- 自定义供应商配置固定使用 `wire_api = "responses"`；只有 CDC 安全密钥模式在未保存密钥时禁止启动。
- 保存或导入供应商配置后，现有插件、MCP、桌面偏好、通知与项目信任配置仍然存在。
