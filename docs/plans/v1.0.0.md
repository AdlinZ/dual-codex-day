# Dual Codex Day v1.0.0 规划

状态：多账号启动器 MVP 已实现，待真实账号验收。

## 版本主题

**本地用量与账号配置统一入口**

Dual Codex Day 把本地用量服务与账号配置启动器合并为一个产品。启动器只调用官方 Codex 客户端，不提供中转、订阅、账号交易或凭据迁移。

## 安全边界

- 每个配置使用随机 ID 对应的独立目录，显示名称不参与路径拼接。
- 独立设置 `CODEX_HOME`、`CODEX_SQLITE_HOME`、VS Code `--user-data-dir` 和桌面客户端 `--user-data-dir`。
- 新配置固定 `cli_auth_credentials_store = "file"`，凭据只由官方 Codex 写入该配置的 `auth.json`。
- 启动器不读取、复制、导入、导出或展示 `auth.json`。
- 启动子进程前清除继承的 `OPENAI_API_KEY`、`CODEX_API_KEY` 和 `CODEX_ACCESS_TOKEN`。
- 默认的 `~/.codex` 不会被迁移或修改。
- 不包含遥测、远程公告、自动更新、第三方订阅或后端服务。

## MVP 范围

1. 创建和列出独立账号配置。
2. 一键打开隔离的 Codex CLI。
3. 一键打开隔离的 VS Code 窗口。
4. 在检测到 Windows 商店版 Codex 时，实验性启动隔离的桌面客户端。
5. 提供可测试的 Node.js 核心、原生 Windows WinForms EXE、PowerShell 回退界面和双击入口。

## 明确不做

- 复制、共享或迁移登录凭据
- 同步不同账号的聊天记录
- 修改微软商店包、`app.asar` 或官方二进制
- 接入 API Key 管理、代充、合租或中转服务
- 自动删除配置目录
- 承诺所有未来 Codex 桌面版本都支持多实例

## 验收标准

- 两个配置生成不同的 Codex、SQLite、VS Code 和桌面数据目录。
- CLI 与 VS Code 同时运行时，退出或登录一个配置不影响另一个配置。
- 桌面端若能启动两个主进程，其命令行必须指向不同的 `--user-data-dir`，其 app-server 必须继承对应 `CODEX_HOME`。
- 默认 `~/.codex` 的配置和凭据文件在测试前后保持不变。
- 自动化测试验证不继承凭据环境变量，且启动器代码不读取 `auth.json`。
- Windows PowerShell 5.1 可以解析图形启动器脚本。
