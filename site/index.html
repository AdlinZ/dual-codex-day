PROFILE CONTROL

把账号、运行环境和用量来源放在同一处

每个 Profile 都有明确的运行状态、登录来源和数据目录。CLI、VS Code 与 Codex 桌面端可以从同一界面启动。

01

独立状态目录

为每个账号分配独立的 CODEX_HOME、SQLite 和客户端用户数据目录。

02

继续最近工作

保存 Profile、工作目录和客户端入口，并支持固定、修复和再次启动。

03

启动前预检

每次启动都重新检查账号、配置和本机入口，阻断项会给出明确处理入口。

LOCAL ANALYTICS

按账号拆分用量，再汇总全局趋势

今天、本周、30 天与全部记录均可按账号、模型和项目筛选。当前周期对比、预算预测、历史周报/月报与分享海报都保留在本地。

  • 输入、缓存输入、输出与推理 Token
  • 模型与项目分布、任务时间轴
  • 自然周/月回看、预算进度与周期末预测

PROVIDER SETTINGS

官方登录与中转站配置各自归档

每个 Profile 可以选择 OpenAI 官方登录，或配置兼容 Responses API 的自定义供应商。已有插件、MCP、桌面偏好和项目信任设置会被保留。

LOCAL-FIRST

数据边界保持清晰

日志只读

扫描本机 Codex Session 并建立增量索引，不修改原始记录。

服务限于本机

用量服务默认只监听 127.0.0.1，不依赖远程分析服务。

认证文件隔离

不读取、复制、导入或展示 auth.json，也不把 API Key 写入 config.toml。

关闭范围受控

仅处理自身记录且通过创建时间校验的进程，不按进程名批量结束。
